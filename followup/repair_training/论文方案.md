## 1. 问题与定位（2026-10-28 13:30 写）

上一篇（《Repairs for Whom?》）证明：在固定候选的单步修复里，用部署者以外的执行者（贪心重放、更强模型、其他家族、裁判）的续跑来**选**修复，部署者会损失价值。
本篇问：把修复当作**训练数据**时（在失败点上以选中的修复动作做 SFT），用谁的续跑来挑目标，会不会改变训练后部署者的表现？

调整后的定位（第 2 节文献的结论）：**检验 CSO 等工作"用策略自己验证训练数据"这一设计选择**——它被当作理所当然（"策略可达性"），但没有人在候选、状态、标签预算都固定时把验证者换掉比较过。经典理论（LOLS）与数学推理上的 PAV 都给出"同策略未必最好"的理由，所以两种结果都有信息量。

### 3.2 样本数相同、由打标签者挑点（2026-10-28 17:07–17:09；探索性；数据同上，没有新数据）

动机（用户 10-28 16:55 讨论后同意）：上面的"全部入选"规则让每个决策点都进训练集，打标签者只能决定**改什么**；而上一篇损失最大的通道是**在哪里改**（规划器知道改什么、不知道在哪里改；14B 与 7B 的修复位置标签一致率 32%）。CSO 中验证的作用也是**过滤**（策略能从这一步完成才保留），不是在候选中排序。

## 4. 研究设计草案（2026-10-28 13:40 写；**未登记**；写时没有任何新数据）

### 4.1 环境与模型
- **主环境 ALFWorld**（理由见第 3 节读法 1）；WebShop 只作第二阶段扩展（读法 3）。
- 部署者 Qwen2.5-7B-Instruct，协议与上一篇相同（温度 0.7、top-p 0.95、50 步、"Thought / Action"格式、历史只含动作与反馈、不可执行时重答至多 2 次）。
- 打标签的执行者：7B 自己（S）、Qwen2.5-14B（X）、7B 贪心（G）；零续跑组：规划器动作不验证（U）、随机候选（R）；探索组：混合（M）。Llama 不作打标签者（差只有 0.036）。

### 4.2 训练（主线：LoRA SFT）
- 样本：失败历史 h_t → `Thought: …\nAction: <目标动作>`。Thought 由冻结的基础 7B 在"给出目标动作"的提示下写（PivotOPD / WebKD 的做法；各组同一程序；提示原文不进入训练文本，含提示用语的样本丢弃后重写）。
- 每个训练集 = 修复样本 + 同一组锚样本（基础 7B 在成功局状态上自己的回答，数量与修复样本相同），防止格式漂移。只在 assistant 部分算损失。
- **各组用相同的种子集合**（同一 LoRA 初始化、同一样本顺序，样本按决策点对齐，只有目标文本不同），让种子噪声在组间相互抵消；先导估计这个相关。
- 超参（LoRA 秩、学习率、轮数）在先导里只定一次，之后各组相同。
- 不选 DPO / PRM 作主线：DPO 多出被拒动作、β、参考模型等变量；PRM 要在测试时再"选"一次，回到上一篇的选择问题。SFT 让"目标是谁挑的"成为唯一变量。DPO 可作主实验后的追加组（另行登记）。

### 4.3 数据与候选
- 训练局：ALFWorld train 中新抽，排除评测局。先导 1,000 局 → 约 370 条失败 → 约 1,100 个决策点；主实验再加 1,000 局（共约 2,200 个决策点）。
- 决策点：每条失败轨迹早 / 中 / 晚三个位置（与 6.9 相同规则：余量 ≥ 5），只保留有规划器动作的点。
- 候选：规划器 + 7B 提 2 + flash 提 2 + 随机 1（约 5.5 个 + 原动作）。不用 14B 提议（上一篇提出者 × 执行者交互 ≈ 0，且省掉 14B 机器上的提议阶段）。
- 标签预算：每个打标签者对每个分支 k = 3 次（贪心 1 次）。强制取 argmax（各组样本数相同）为主；"估计收益 > 0 才入选"为次要。

### 4.4 读数
- **接管成功率（建议作打标签者比较的主读数）**：基础 7B 在留出游戏上失败的轨迹，早 / 中 / 晚三个位置；训练后的模型从该历史自己选动作并续跑 m 次。基础模型在这类点上约 0.10（6.9 原动作分支 0.104），把规划器动作强行放进去是 0.72，上升空间大。

### 4.5 功效（假设，待先导校准）

### 5.2 游戏（ALFWorld 2.1.1；全部排除 pick_two_obj_and_place）

- 每个游戏的环境种子 = `derive_seed("RT1", gamefile)`；PYTHONHASHSEED=0。

### 5.3 决策点、候选、标签（沿用 6.9 的 ds_alfw 逻辑，只换游戏）
- 采集：7B 在 1,000 局各跑 1 次（部署协议；**保存每步的原始生成文本**，用于锚样本）。预计约 37% 失败（6.9：82 / 220），约 370 条失败轨迹。
- 位置：每条失败轨迹在余量 ≥ 5 的步中分早 / 中 / 晚三段各随机取 1 步（种子 `derive_seed("RT2", rid)`）；只保留规划器给出下一步的点。预计约 1,100 个决策点。**全部失败轨迹都用**（不按 rid 截断），只排除没有可选位置的。
- 候选：规划器动作 + 7B 提 2 个 + Qwen3.8-flash（API，不思考）提 2 个 + 1 条随机可执行命令（去重；与原动作相同的去掉）。提议提示与 6.9 相同（删去 14B 提议者）。
- 标签：7B 对每个决策点的原动作与每个候选各续跑 **k = 3** 次（温度 0.7、top-p 0.95、每请求单独种子）。

### 5.4 训练集（各组样本数相同）
- 记决策点数为 D，**N = round(D / 2)**。
- **S（7B 自选）**：ĝ = max_a [ŝ(a) − ŝ(原动作)]（ŝ 为 3 次续跑的成功率）；按 ĝ 取前 N 个点（并列用 `derive_seed("RT3", 点 id)` 打破），每点目标 = argmax 候选（候选间并列同样打破）。
- **U（规划器不验证）**：随机 N 个点（种子 2034）+ 规划器动作。
- **R（随机候选）**：随机 N 个点（与 U **相同**的点集）+ 每点随机一个候选（种子 2035）。
- **锚样本**：从 1,000 局里的成功局的全部步中随机抽 N 个状态（种子 2036），目标 = 7B 当时自己的原始输出（Thought + Action）。各组共用同一组锚样本。
- **Thought 改写**（各组同一程序）：冻结的基础 7B 读与部署相同的提示，再追加"The next action is: <a>. Write a short Thought (one or two sentences) explaining, from the information above, why this is a good next step. Do not mention that the action was given to you."；先用贪心生成。若 Thought 含提示用语（given / provided / suggested / hint / told / instructed / "next action is" 等，表在代码中固定）或无法解析，用温度 0.7 重写，至多 3 次；仍不行则用模板"Thought: I will <a>."。训练文本 = `Thought: <t>\nAction: <a>`。逐组报告重写次数与模板比例（描述性）。
- 样本格式：提示 = 该历史下部署协议的完整提示（系统 + 用户），助手 = 上述文本；**只在助手部分算损失**；长于 6,144 token 的样本丢弃并计数（6.9 的最长提示 5,148）。

### 5.5 训练
- LoRA：秩 16、α 32、dropout 0.05，作用于 q/k/v/o/gate/up/down；bf16、梯度检查点；学习率 1e-4（余弦，3% 预热）；2 轮；等效批量 16；AdamW（权重衰减 0）。**这些值在先导中只定一次**，各组相同。
- 种子：S 用 {11, 12, 13}，U、R 用 {11, 12}，DPO-S 用 {11}。种子决定 LoRA 初始化与样本顺序：每组的样本按"槽位"排列（第 i 个修复样本按决策点 id 的哈希排序，锚样本按抽样顺序，交替排成 2N 个槽位），同一种子在各组用同一个槽位排列；各组只有槽位里的内容不同。
- DPO-S（次要，探索性）：被选目标 = S 的目标，被拒 = 该点原动作（Thought 用同一程序改写）；β = 0.1；参考 = 关掉 adapter 的基础 7B；损失 = 修复对上的 DPO + 锚样本上的 SFT（权重 1）；学习率 2e-5，其余同上。
- **格式检查**（看读数之前）：每个训练后的模型在 50 个冒烟局上跑 1 次，只看不可执行 / 无法解析动作占步骤的比例。若任一组比基础模型高 5 个百分点以上，允许**一次**修改超参（所有组一起改），依据只能是这个比例；修改记在本节。

### 5.6 读数（每个模型：B = 基础 7B，以及 8 个 LoRA 模型）
- **接管成功率（主）**：基础 7B 在 E 上另跑 1 次（种子 `derive_seed("TK", gamefile)`，与端到端评测不同），按 E 的抽样顺序取前 200 条有可选位置的失败轨迹，每条早 / 中 / 晚各 1 个点（同 5.3 规则，种子 `derive_seed("TK2", rid)`），P = 600。每个模型从每个点的历史开始**自己选动作**并续跑到 50 步，m = 3 次；各模型在同一点上用相同的请求种子序列（共同随机数）。点的值 = m 次的成功率；组的值 = P 个点的平均。
- **端到端成功率（次要；阳性对照判定要用）**：每个模型在 E 的每局跑 1 次，各模型同一局用相同的种子序列。
- **新数据上的目标质量 q̄**：S 的 N 个目标与对应原动作各用基础 7B 再续跑 3 次（新鲜续跑，选择时没用过），q̄_S = 平均净收益。U、R 的点不是靠续跑挑的，直接用 5.3 的 k = 3 标签估计 q̄_U、q̄_R。
- 描述性：训练后的模型在接管点上第一步的动作是否等于规划器动作；不可执行率；平均步数。

### 5.7 统计
- 每组先在种子之间平均每局（每点）的结果，再做配对比较。区间：重抽评测局（端到端）或接管轨迹（接管；同一轨迹的 3 个点一起抽）2,000 次的百分位区间；"90% 下界" = 第 5 百分位。**先导的区间只反映评测局的抽样、把种子当作固定**；种子 SD 单独报告。
- 种子 SD：S 3 个种子的组均值的 SD；同种子组间相关：用种子 11、12 上 S、U、R 的组均值估计 Var(S_i − U_i) 与 Var(S_i) + Var(U_i) 的比。只有 2–3 个种子，这两个量很粗；主实验的功效计算取它们的保守端（种子 SD 取 S 的 3 个种子的极差，组间相关取估计值与 0.3 中较小者）。
- Γ_take = (S − B)_接管 / q̄_S；Γ_e2e 同理。线性检查（探索性）：(U − B) / q̄_U、(R − B) / q̄_R 与 Γ 比较。

### 5.8 判定（运行前固定）
- **通过** = S − B 端到端 ≥ +0.03 且 90% 下界 > 0，**并且** S − R 接管 ≥ +0.10 且 90% 下界 > 0。
- 只有接管一项通过 → 主实验照做，端到端只作描述，论文不声称部署收益。
- 接管一项不通过 → 停：单步修复 SFT 在这个部署者上没有稳定效果，打标签者问题不成立；如实报告，再决定是否改 DPO 或多轮 DAgger（另行登记）。
- **主实验做不做还要看功效**：用 Γ_take × 0.234（3.2 节前 50% 的 S − X 目标差；主实验会用 14B 标签重估）作 S − X 的预期差，按 5.7 的保守种子 SD 与组间相关，P = 1,000、m = 4：若 ≤ 5 个种子能达到 0.8 功效，且主实验总计 ≤ 150 卡时，就做；否则不做主实验，先改训练量或读数（另行登记）。

### 5.11 实现补充（2026-10-28 17:37 写，写代码时确定；写时**没有任何新数据**；代码在 `D:\Paper\repair_training`，见 README.md）
这些是 5.2–5.8 没写到、在代码里必须定下来的细节。都在看任何新数据之前确定，之后改动要另记。
1. **评测局顺序**：E 排序后用种子 2037 打乱，接管来源按这个顺序取失败轨迹。避免按来源顺序取时偏向 6.9 的局。
2. **训练点 / 接管点**：训练点要求规划器给出下一步、且不同于原动作、且可执行（5.3）。接管点只要求余量 ≥ 5（同样分早 / 中 / 晚各取 1 个），不要求有规划器动作，因为接管时模型自己选动作。
3. **并列**：候选之间用 derive_seed("RT3", 点, 动作) 取较大者；点之间用 derive_seed("RT3", 点) 取较大者。R 的随机候选从该点全部候选（含规划器动作）里取。
4. **锚样本**：只从成功局中"第一次回答就可执行、没有重答"的步里抽（重答后的输出是在多轮上下文里生成的，与单轮提示不一致）。
5. **Thought 改写**：先贪心 1 次，再用温度 0.7 至多 3 次，最多 160 token。提示用语按正则拦下：given action / provided action / suggested / suggestion / hint / told to / instruct / next action is / as specified / I was asked / the next action / action provided 等，原文见 `rt_data.LEAK_RE`。普通的 "Given that…" 不拦。
6. **训练**：微批 1 个样本，16 个样本一次优化步；SFT 损失按样本内 token 平均；梯度裁剪 1.0；bf16 + 梯度检查点。槽位 2i 是第 i 个修复样本（按决策点 id 的哈希排序），2i + 1 是第 i 个锚样本；每轮的排列只由 (种子, 轮次) 决定。DPO 的参考对数概率在训练前算一次（关掉 adapter、eval 模式）。
7. **评测**：基础模型 B 也在开了 LoRA 的同一个 vLLM 引擎里评测（不带 adapter），数值路径与 LoRA 模型一致。同一模型的接管与端到端放在一次续跑里。请求种子：端到端 derive_seed("E2E", 局)，接管 derive_seed("TKR", 点, k)，格式检查 derive_seed("FMT", 局)，各模型相同（共同随机数）。
8. **格式检查指标**：第一次回答就不可执行或无法解析的步，占策略步数的比例（重答之前）。
9. **分析**：同种子组间相关用两个共同种子的方差公式 1 − Var(差) / (Var(x) + Var(y)) 估计，Var 用 (x₁ − x₂)² / 2。主实验功效里的组 × 点交互 SD τ 取估计值与 0.2 中较大者。主实验卡时从本次计时外推（7B 标签、每次训练、每个模型的评测），只用于 5.8 的决定。
10. **冒烟**（`out_rt_smoke/`，结果不进入任何读数）：只用 50 个冒烟局（30 局训练 + 16 局评测 + 最后 6 局格式检查）、12 个决策点、K = 2；只训练 S_s11 与 DPO-S_s11，各 1 轮。正式 P0 的格式检查用全部 50 个冒烟局；冒烟训练出的 adapter 不用于 P0。
11. **断点续跑与签名**：数据阶段的设置签名不含训练 / 评测设置，所以按 5.5 改超参不会让已采的数据失效。续跑结果逐条落盘，签名不同的旧结果拒绝混用。
