## 一、一句话主张（Gridworld 中已确认；推广性待第二环境检验）

**归因与修复方法在挑选“在哪一步、换成什么动作”时，常用一个与部署策略不同的条件来评估反事实结果——环境可恢复性、确定性（贪心）重放、少量重跑、或另一个模型。我们在可精确控制的环境中测量这种做法让修复在部署策略下损失多少，找出损失的来源，并给出代价低的修正。**

暂定标题（二选一，待结果定）：

- *Attribution for Whose Continuation? Measuring When Proxy Evaluators Pick the Wrong Repair*
- *Repairs That Don't Transfer: Evaluator–Executor Mismatch in Counterfactual Failure Attribution*

## 二、研究问题与动机

### 2.1 问题

给定一条失败轨迹、一组固定的候选修复（位置 t × 替代动作 a′），记部署条件为 c₀（部署策略、解码设置、预算），评估条件为 c。用 c 估计每个候选的净收益并选出 î(c)，再在 c₀ 下执行。

- **主问题**：R_{c₀}(î(c₀)) − R_{c₀}(î(c)) 有多大？哪些 c 是安全的？
- **机制问题**：损失来自“选错位置”还是“位置对了但选错动作”？与可恢复性、剩余余量（slack）、策略能力有什么关系？
- **改进问题**：有没有代价低、可以替代“用部署策略大量采样”的评估方式？

### 2.1b 两个必须分开的维度与两个目标（2026-10-22 修订，采纳外部审阅意见）

**维度一：评估对象不一致**（估计的已不是部署策略的成功率）：oracle 用可解性代替成功率；贪心是另一个（确定性）策略；温度 0.3 是相近但不同的解码。这是“评估者与执行者不一致”的核心证据。

**维度二：评估预算不足**（估计目标不变，样本太少）：同一部署策略只跑 3/5/10 次。DoVer 每个干预跑 3 次；本文的 k = 3 条件是“用 3 个样本给固定候选排序”，与完整 DoVer 流程不同，写作“受其验证预算启发的受控实验”。

论文必须分开报告两个维度，否则会被概括为“采样越多越准”。CAR 与 Credit Without Ground Truth 已经使用同策略续跑（已核实），所以本文的区分点不是“反事实效果依赖策略”本身，而是**修复选择在部署下的损失、损失机制与低成本纠正**。

**两个目标**：净收益 R = p(替代) − p(原动作)（主目标）与修复后成功率 p(替代)（次要目标）。同一位置上两者排序一致；跨位置时基线不同，排序可能不同（例如 0.60→0.90 与 0.05→0.50）。两者都报告。不可逆点上原动作分支成功率为 0，两者相同。

**参照不是真实最优**：“按部署策略选择”本身是有限样本（每折 20 次）的选择；独立评价消除了选择与评价复用的乐观偏差，但参照并不等于真实最优修复。

### 2.2 为什么这不是“显然的”

“最优修复依赖续跑策略”在原理上是平凡的（任意构造两个擅长不同子任务的策略即可反转）。论文的价值不在于证明存在性，而在于：

1. 在**实际被使用的评估做法**下，损失有多大；
2. 损失有**可解释、可预测**的来源；
3. 存在**可操作**的修正。

### 2.3 实际做法与我们的对应条件

| 做法 | 出处（核实状态） | 本文对应条件 |
|---|---|---|
| 只跑少量次数判定修复是否有效（每个干预 3 次，≥2 次成功即“验证通过”） | DoVer，2512.06749（已核实） | 部署策略只用前 k 次采样（k = 3/5/10）；受其验证预算启发，不是完整复现 |
| 纠正动作由另一个能看到标准答案的强模型提出；取“最早一个纠正后足以成功的步骤” | AgenTracer，2509.03312（已核实；重新模拟由谁执行、几次，原文未说明） | 候选来源 μ ≠ π；“最早充分位置”规则 |
| 同策略重采样，取“效应区间不含零的最晚步骤”（point of commitment） | CAR，2606.08275（已核实） | “最晚显著位置”规则 |
| 以环境可恢复性 / 不可逆点为准定位与修复 | 合成环境中的常见做法（本文归纳，需在论文中给出具体例子，待补） | oracle 条件（成功当且仅当 F=1） |
| 温度 0 的确定性重放以求可复现 | CAR 讨论了本地固定种子模型可精确重放（已核实）；是否有方法以此为标准做法，待核实 | 贪心解码条件 |
| 更强模型代替部署模型续跑 | CAR 定义了 do_policy 但未报告结果（已核实）；CVT-RL 用冻结参考策略续跑（摘要级） | （可选）32B 续跑条件 |

## 三、测量对象与协议

### 3.1 三个量（沿用原方案的定义）

- **V^π(h)**：从历史 h 起按策略 π 续跑、在剩余预算内成功的概率。
- **F(h)**：剩余预算内是否存在成功的动作序列（环境可解性；gridworld 中可精确计算）。
- **R_t(a′)**：在 h_t 用 a′ 代替原动作的净收益 = V(替代分支) − V(原动作分支)，两个分支都采样。

### 3.2 主指标：相对匹配选择的损失

用 c₀ 本身、同样采样数、**独立随机流**的批次做选择，作为参照；所有选择都在 c₀ 的**另一批独立样本**上评价（或两折交叉拟合）。两者在同一批样本上比较，所以不需要“验证集上的最大值”，不受赢家诅咒影响。

### 3.3 防止“看起来安全”的阳性对照

随机挑一个候选，相对匹配选择的损失必须被确认 > δ；否则说明部署策略在这些状态上几乎没有恢复能力（地板效应），任何“安全”结论都不成立。

### 3.4 干预协议

- 候选动作：全部合法动作，**不依赖模型提议**，避免“没找到修复”只是生成器的问题；
- 续跑提示只含“动作 + 环境返回结果”，不含模型的 Thought，替换动作不会与旧推理矛盾；
- 预算内无解（F=0）或已结束的分支，结果对任何策略都确定，不采样；
- 所有随机性由逐请求种子控制，选择批次与验证批次互相独立、可复现。

### 4.2 探索性发现（看过数据后得到，必须在新数据上确认）

1. **地板效应集中且可由失败类型预测**：只有 8/20 条轨迹存在净收益 > 0.10 的单步修复。timeout_before_door 0/5，timeout_return 4/5，trap_step 4/10。平均损失被稀释约 20/8 倍；在 8 条有信号的轨迹上，贪心损失约 0.38，oracle 约 0.24。
2. **贪心重放几乎是一条确定性轨迹**：2 次采样在 439/440 个分支上完全一致，89.5% 的分支结果为 0；无法区分哪些修复对采样策略有用，最优并列平均 16 个，选择接近随机。
3. **可恢复性太粗（动作层面）**：在不可逆的那一步，多个动作都能恢复 F=1，但 7B 的成功率差异极大（例如 ep0055：move:down +0.75，open +0.06）。若 oracle 并列时按剩余余量（slack）打破，损失从 0.095 降到 0.050。
4. **不可逆点不是最佳修复点（位置层面）**：8 条有信号的轨迹中有 3 条，对 7B 最好的修复在更早、仍可恢复的位置（例如 ep0108：第 8 步修复 +0.62，不可逆的第 16 步修复 +0.12，因为剩余步数太少 7B 走不完）。受 CAR 启发的“最晚显著位置”规则损失 0.041（有信号轨迹上 0.104），与“固定选最后可恢复位置”几乎相同。
5. 温度 0.3 在 v1 中区间上界低于 0.10。但 v1 的 20 条轨迹中有 12 条是地板，平均损失被稀释（有信号的 ep0060 上损失 0.41）；这**不等于**在新总体中安全，确认实验中以 C6 重新检验。

## 五、确认性假设（quick 实验，已完成，结果见 5.1）

22 条从未用过的新轨迹（timeout_return 14 条全取，trap_step 随机 8 条），每条取不可逆点 + 一个更早的可恢复位置；部署条件每分支 40 次两折交叉拟合，贪心每分支 1 次；约 8,650 条续跑。

| 假设 | 统计量 | 确认标准 |
|---|---|---|
| H1 可恢复性太粗 | 不可逆点上：按 7B 选动作 − 在可恢复动作中随机选 | 90% 区间下界 > 0 |
| H2 不可逆点不是最佳修复点 | 两个位置中按 7B 选 − 只在不可逆点按 7B 选 | 同上 |
| H3 贪心重放选不准 | 按 7B 采样选 − 按贪心重放选 | 同上 |
| 阳性对照 | 按 7B 采样选 − 随机选 | 下界 > 0.10，否则整体无判别力 |

已知局限：H1 只能在不可逆点有 ≥ 2 个可恢复动作的轨迹上检验（约 11 条），功效偏低。

**决策**：H1 或 H2 至少一个确认 → 进入第六节的完整实验；都未确认 → v1 的机制可能是开发集噪声，停止扩规模，回到问题定义重新评估方向。

- **oracle 选择损失在新数据上复现**：v1 为 0.095 [0.020, 0.145]，quick 为 0.094 [0.010, 0.149]。其主要来源是 H1（不可逆点上选错动作），而不是位置。

**据此调整**：

1. 主结论围绕两点：(a) 可恢复性 / 不可逆点只能告诉你“在哪里”，不能告诉你“换成什么”，后者对弱策略的收益差别很大；(b) 确定性（贪心）重放与少量重跑会选错修复。
2. **H2 不再作为主张**。“不可逆点不是最佳修复点”在 22 条新轨迹中只有 2 条明显成立，作为案例与局限讨论；若以后要重新检验，须作为新的事先登记假设（例如每条轨迹取多个更早位置），不能用现有数据换个分析方式重新检验。
3. 定位规则（最早充分 / 最晚显著）的比较保留为次要分析，预期差异不大。

### 5.2 部署策略有效性检查（2026-10-22）

目的：排除“7B 不会做题是代码或框架造成的”。

**无 GPU 审计（out_120，120 局、2,579 个决策步）**：解析器重新解析与保存动作 0 处不一致；全部输出正常结束、无截断；逐步重放与保存状态全部一致；续跑与采集消息协议相同（自检）；用独立实现重新推导观测中的四方向后果、目标方位与地图位置，0 处错误。失败特征：可解状态中单步选到最优动作 66.7%（“拿钥匙后去开门”阶段 50.5%）；17% 的移动走进观测中明确标注为墙/门/陷阱的方向；撞墙后 43% 重复同一动作；Thought 与动作只有 3.3% 不一致（错误在推理，不在解析）。

论文写法：明确部署策略是“在该任务上单步正确率约 0.67–0.75 的 7B 智能体”，并报告上述检查。

## 六、完整实验计划（quick 已通过：H1、H3 确认）

完整实验的目标是**把效应量估准**（目前区间下界接近 0），并检验改进方法与推广性；不再检验 H2。

### 6.1 Gridworld 确认实验（主结果）——事先登记（2026-10-22 15:40，跑模型之前）

实现：`confirm.py`（设置写在文件顶部常量中，设计文件记录全部设置、假设文本与代码哈希）。分两阶段运行：`confirm-prep`（采集 + 筛选）结束后先检查筛选结果，再运行 `confirm-run`（主实验 + 分析）。15:45 的改动只涉及运行入口与筛选结果的输出，不改变任何设置或检验。

| 环节 | 规则 |
|---|---|
| 采集 | 全新地图种子 1000–1199，共 200 局；部署策略、提示、解码与 pilot 完全相同（批量推进，逐请求种子） |
| 候选总体 | 失败类型为 trap_step 或 timeout_return 的轨迹 |
| 筛选 | 在不可逆点（最后一个预算内可解位置）上，对每个替代动作用独立批次续跑 10 次；任一动作 ≥ 3/10 成功即“有信号”。筛选结果不参与任何选择或评价 |
| 停止条件 | 有信号的轨迹少于 20 条 → 停止，不跑主实验 |
| 主实验样本 | 有信号的轨迹，至多 30 条（超过时固定种子随机取） |
| 位置与候选 | 最后可解位置 + 3 个分段随机的更早可解位置；全部合法替代动作 |
| 采样 | 部署策略每分支 40 次（两折各 20，交叉拟合），前 4 次保存逐步记录；贪心每分支 1 次并保存记录；oracle 不用 GPU |
| 主检验（Holm 校正，单侧家族 α = 0.05） | **C1** 不可逆点上按部署策略选动作 − 在能恢复可解性的动作中随机选 > 0；**C2** 按部署策略选 − 按贪心重放选 > 0；**C3** 按部署策略选 − 按 oracle 选 > 0 |
| 次要检验（90% 区间下界 > 0） | **C4** 20 次选 − 3 次选 > 0（评估预算维度；受 DoVer 启发）；**C5** oracle 按 slack 打破并列 − 纯 oracle > 0 |
| 候选安全代理（修订 1） | **C6** 按部署策略选 − 按温度 0.3（每分支 20 次）选：上界 < 0.10 → “在 δ 内可接受”；下界 > 0 → “选错” |
| 目标（修订 1） | 主目标净收益；同时报告修复后成功率下的同组比较 |
| 机制 | **M1** 撞墙/撞门后重复同一动作的比例：贪心 > 采样 |

| 只描述、不检验 | k = 5/10 的选择损失；定位规则（最后可恢复 / 最晚显著 / 最早充分）相对部署最优的损失 |

### 6.1d 已发表方法的评估环节（事后分析，2026-10-22 23:40；确认实验结果公布之后加入，只作探索性证据）

读法与限制：
- 这里的重放**全部由部署策略本身执行**，所以损失来自“判定规则 + 样本量”，不是评估者与执行者不一致。真实方法常由更强的模型生成或验证修复，会在此基础上再叠加不一致带来的损失。
- “接受即可”的规则（翻转、2/3）不在接受者之间排序，而通过验证的修复里有很多在部署条件下成功率很低（单次或 3 次样本碰巧成功），这是损失的主要来源；“最早”规则又偏向早期位置，那里的修复对结局影响小。CAR 式规则用 20 次同策略样本，几乎无损，与我们的主张一致（同策略 + 足够样本是安全的）。
- 事后加入，需在 ALFWorld 阶段 B 中事先登记后确认。
- **LLM 裁判（只判断、不执行，2026-10-22/23 运行；2026-10-23 起裁判改用千问，以下 DeepSeek 结果保留作附录，见 6.3c）**：7B 自评损失 +0.592 [+0.457, +0.670]，与随机相当。DeepSeek-flash 思考模式（7 条首次被截断，32k 上限重问后 34/34 有效）损失 **+0.085 [−0.000, +0.149]**。消融（配对比较）：去掉“执行者是温度 0.7 的 7B”这句话，差 +0.009 [−0.059, +0.072]，34 条中 28 条选择相同——**执行者信息不起作用**；关闭思考，差 +0.179 [+0.067, +0.289]——**推理是关键**。与其他条件配对：比 oracle 好 +0.101 [+0.008, +0.163]，比贪心好 +0.139，比“oracle + 余量”略差 −0.048 [−0.113, −0.001]，与部署 3 次相当 +0.024。读法：强推理裁判做的事接近“环境最优 + 偏好余量大的修复”，而不是模拟这个弱执行者；在 gridworld 里 oracle + 余量本来就接近匹配选择（差 +0.038 [−0.034, +0.075]，即 C5）。所以这不构成新方法，而是 C5 的又一个实例；关键问题留给 ALFWorld：部分可观测、长周期下，“懂环境 + 偏好余量”是否仍然够用。

原计划要点（保留作背景）：

### 6.3b ALFWorld 阶段 B（主实验）——事先登记（2026-10-23 01:45，采集之前）

实现：`alfw_stage_b.py`（自检 `alfw_selftest_b.py`）；设置在 `alfw/acfg.py` 的 `B_*`；分析调用与 gridworld 确认实验**同一段代码**（`confirm._selection_values`，只把 oracle 换成 ALFWorld 规划器）。分两段运行：`bash run_bg.sh alfw-b-prep`（采集 → 设计 → 筛选 → 选择，看完筛选结果再决定）与 `bash run_bg.sh alfw-b-run`（主实验 → 分析）。

**总体与样本**
- 游戏：train 中新抽 300 局（种子 2027），排除 A2、A4 用过的游戏（共 100 局；A2 的 20 局恰好包含在 A4 的 100 局中），事先排除“拿两个物品”任务（A4 中成功率 4–6%，地板）。部署条件（7B，温度 0.7，阶段 A 修正后的协议）各跑 1 局，失败轨迹中固定种子取至多 100 条进入筛选。
- 位置：每条轨迹在每一步求规划长度 L(t)；余量 (50 − t) − L(t) ≥ 5 的步为可选位置（规划超时的步不可选），按先后均分为早 / 中 / 晚三段，各随机取一个；不足 3 个则全取。最晚的位置标为 decisive（ALFWorld 无不可逆点）。
- 候选：规划器建议的下一步（若与原动作相同则不用）+ 随机可执行命令，共 6 个替代动作，加原动作分支。每个分支再求一次规划：oracle 可行性 F = [L ≤ 剩余步数]，余量 = 剩余 − L；分支规划超时按 F = 1、余量最低处理并报告数量；动作直接完成任务的分支为确定性成功。
- 筛选（独立批次，部署条件）：原动作分支与替代分支各 4 次；**有信号** = 某位置上某替代分支比原动作分支多成功 ≥ 2 次。与 gridworld 不同，原动作分支在 ALFWorld 中成功率不为 0，因此筛选看净差。有信号的轨迹不足 20 条即停止，不进入主实验。筛选数据不参与任何选择或评价。总体表述为“部署策略的失败轨迹中，存在单步修复信号的那些”。
- 主实验：有信号的轨迹中固定种子取至多 30 条；部署条件每个随机分支 30 次（两折各 15，交叉拟合）、贪心 1 次。温度 0.3 不跑（gridworld C6 已确认损失小）。

**检验**（δ = 0.10，90% 区间，轨迹聚类 + 部署样本参数 bootstrap，2000 次）
- 主检验 B2–B4，Holm 校正（单侧 α = 0.05）：B2 匹配 − 贪心 > 0；B3 匹配 − oracle（并列平均）> 0；B4 匹配（15 次）− 3 次 > 0。
- 阳性对照：匹配 − 随机的下界 > δ，否则全部判为“无判别力”。
- 次要：B5 oracle + 余量 − oracle > 0；B6 匹配 − oracle + 余量（三分类：下界 > 0 选错 / 上界 < δ 在 δ 内安全 / 不确定）；B7 匹配 − 规划器建议步（各位置平均）> 0；B8 匹配 − DeepSeek 思考版裁判（三分类同 B6）；B9 匹配 − 7B 自评裁判 > 0。
- 描述：四种已发表方法的判定规则（DoVer 2/3、CausalFlow 翻转、AgenTracer/REFLECT 最早充分、CAR 最晚显著）；修复后成功率目标；部署与贪心续跑的步数、不可执行率、回到已到过状态的比例；最佳候选是规划器建议步的比例；有信号轨迹占筛选轨迹的比例（单步修复的适用范围）。
- 裁判与 gridworld 用同一种提示结构（写明执行者是温度 0.7 的 7B），候选顺序按轨迹固定种子打乱；DeepSeek-flash 思考模式，被截断的用更大上限重问。

**预期与读法**（写在运行之前）
- 预期 B2、B4 确认（贪心在绕圈的 7B 上更容易卡死；少量样本噪声大）。B3 方向不确定：ALFWorld 中 oracle 几乎处处并列（失败局第 40 步前几乎都“来得及”），oracle 选择接近随机，若确认则是“可恢复性没有分辨力”的又一证据。
- 关键问题是 B6 与 B8：在 gridworld 中 oracle + 余量与 DeepSeek 裁判都接近匹配选择。若在部分可观测、长周期、7B 大量绕圈的 ALFWorld 中两者都“选错”，主张就是“评估者越懂环境不等于越懂执行者”；若仍“在 δ 内安全”，论文须承认“懂环境 + 偏好余量”是可行的替代方案，主张收窄为“按另一个策略执行（贪心、少量样本、按可恢复性）会选错”。
- 修订规则：运行之后的任何修改都记入修订记录，注明时间与是否看过数据。
- 运行方式修订（2026-10-23 02:05，任何阶段 B 数据产生之前）：取消“筛选后人工查看再继续”的检查点。改为先做冒烟测试（真实 7B、另一种子、极小规模：16 局、4 条轨迹筛选、2 条进主实验，结果写入 out_alfw_b_smoke/ 且不参与任何分析），通过后自动连续运行正式实验；停止规则（有信号不足 20 条）仍自动执行。

### 6.6 方法：环境信号筛选 + 部署策略续跑（离线评估）——开发集结果与定稿（2026-10-23 22:10，看留出数据之前）

实现：`method_cascade.py`。依据已有发现设计：“换成什么动作”可以交给懂环境的信号，“在哪一步换”只能靠部署策略自己的续跑。
- 方法 SL(m, k)：每个位置只留环境信号（可解性 × 1000 + 余量）最好的 m 个替代动作；只对这些候选及其原动作分支各跑 k 次部署续跑；选净收益估计最高的。变体 SL-SH：筛选后逐轮淘汰分配预算。

### 6.8 共享修复代价：区分“分辨率丧失”与“真实偏好冲突”（2026-10-23 23:05 登记，计算之前；事后分析，探索性）

**状态**：同一批数据上的交叉选择损失（6.3d、6.5）、排序一致性、位置标签一致率与方法排名（6.7）都已看过；本节的统计量此前**没有计算过**。全部为探索性，不做多重比较校正，不能当确认性证据报告。起因是外部备忘录（2026-10-23）指出：跨执行者的选择损失 L 可能只来自代理执行者“分不出好坏”（例如 flash 几乎从哪里都能成功，净收益被压平），而不是两个执行者真的偏好不同修复；只有后者才说明数据集必须按执行者分别打标签。

实现：`share_gap.py`（只用已有数据，不需要 GPU）。数据：D1 = ALFWorld 阶段 B（30 条，筛选后有信号）+ 阶梯；D2 = gridworld 确认实验（34 条，筛选后有信号）+ 阶梯；D3 = gridworld q7 池（100 条不筛选）× 7B / 14B 评估（14B 评估跑完后再算，`ds_gw.py` 的两阶段设计）。

**定义**（对一条轨迹，候选 r，执行者 e 的净收益 R_e(r)；执行者对 (A, B)）：
- 个人选择 pick_e = argmax R̂_e（e 自己选择样本上的净收益）；共享选择 pick_AB = argmax (R̂_A + R̂_B)/2；并列时对并列集合取平均。
- 交叉损失 L_{A→B} = V_B(pick_B) − V_B(pick_A)（两个方向都报）。
- 以 B 为目标的共享代价 Δ_B = V_B(pick_B) − V_B(pick_AB)；**共享修复代价 G_AB = (Δ_A + Δ_B)/2**（三个执行者时 G3 = 三者 Δ 的平均）。真值 ≥ 0；接近 0 表示存在一个对两个执行者都接近最好的修复，排序不同不一定需要分别打标签。
- 反转率：同一条轨迹上 L_{A→B} > 0 且 L_{B→A} > 0（各自用对方的选择会更差）的比例。
- 选择余地（分辨率的描述量）：V_e(pick_e) − V_e(随机)，即用 e 自己的标签挑选能比随机多得多少。
- V 一律在与选择不相交的样本上评价。

**估计**：
- D1 / D2：每个执行者用相同样本数（10 次；7B 有 30 / 40 次，切成 10 次一块，结果对各块取平均），每块对半分（5 选 5 评）并交叉拟合；对每个分支内的样本做 50 次随机重排、取平均（样本可交换，只降低切分带来的方差）。确定性分支（gridworld 的立即成败）对所有执行者取同一值。
- D3：按数据集设计，用 S1a 选、用与挑选无关的无偏标签（6.5）评价，不交叉拟合；共享选择用两个执行者 S1a 净收益的平均。
- 区间：每条轨迹一个统计量，轨迹 bootstrap 2,000 次，90% 百分位区间（不用参数 bootstrap，因此没有 6.3c 修订中的收缩偏移问题）。
- **噪声参照**（有限样本下 Ĝ 不是 G 的无偏估计：个人选择只用一个执行者的 5 次、共享选择用两个执行者的 5 + 5 次，噪声不同；方向通常使 Ĝ 偏低，但不保证）：(i) 参数零假设模拟——每个分支两个执行者的真实成功率都设为合并估计 (k_A + k_B + 0.5)/(n_A + n_B + 1)，按完全相同的样本结构模拟 200 次，报告 Ĝ、L、反转率在零假设下的均值与 95% 分位；(ii) 经验参照（只 D1 / D2）——把 7B 两个不相交的 10 次块当作两个“执行者”，真值 G = L = 0。主读数为 **Ĝ − 零假设均值**（区间来自 Ĝ 的 bootstrap，零假设均值视为固定）。

**读法（事先固定）**，主对 (7B, 14B)：
1. ALFWorld 中 Ĝ − 零假设均值 的区间下界 > 0 → 7B 与 14B 存在真实的偏好冲突；数据集保持“按执行者分别打标签”为核心。
2. 两个环境的区间都含 0 且上界 < 0.05（与 6.5 的阈值一致）→ 跨执行者损失主要来自分辨率 / 噪声；按备忘录 7.2 第 3 行收窄主张（代理评估的分辨率与选择不确定性），执行者条件标签降为附加信息。
3. 其余 → 不能区分；等 D3（100 条不筛选）与 ALFWorld 数据集的两阶段标签再判断，不据此改动数据集设计。
- 次要：(7B, flash) 同样计算；三执行者 G3 只作描述。另报 Δ_7B 与 L_{14B→7B} 之比（共享标签能挽回多少交叉损失）。

**预测**（写在计算之前）：

**6.13 正式实验：WebShop 上的不筛选失败 × 穷举候选 × 7B / Llama 执行者（2026-10-26 21:30 登记；写代码与任何采集之前）**

结构照 ALFWorld 6.9 与 6.10，有两个部署池：WS-A 部署 7B，执行者是 7B、Llama，14B 晚到；WS-B 部署 Llama，执行者是 Llama、7B。用户 10-26 决定两个池都做。理由：ALFWorld 的“执行者依赖双向成立”（H1、H2）是论文的主要结论之一，在第二个环境上只复现一个方向不够。实现放在 `webshop/ws_formal.py`。

- **目标**：1,021 个人写目标中去掉冒烟用过的 60 个。WS-A 按 `random.Random(4001)` 打乱的顺序，WS-B 按 `random.Random(4002)` 打乱的顺序，并排除 WS-A 采集用过的全部目标。
- **采集**：部署模型每个目标跑 1 局（温度 0.7，最多 25 步，协议与冒烟相同），每 100 个目标一块。失败达到 70 条的那一块跑完就停（最多 600 个目标）。**失败 = 奖励 < 1**（买错和超时都算）。按顺序取前 60 条至少有一个可选位置的失败，**不看任何修复信号**；排除数单独报告。
- **位置**：修改之后至少还要剩 5 步，即第 t 步（从 1 起）要满足 t ≤ 20，且不晚于轨迹长度。可选的步按先后均分为早、中、晚三段，每段随机取一步，种子由轨迹编号确定；不足 3 步时全取。位置在生成候选之前固定。
- **候选**（任何续跑之前冻结；每个位置按下面五类取并集、去重，记录每个候选的全部来源；原动作分支一并续跑）：
  1. **穷举**：该页全部可点击项（按钮、商品编号、选项、buy now）中与原动作不同的。WebShop 每页可执行的动作有限，可以全部列出，候选集合不依赖提出者。
  2. **模型提议**（与 6.9 相同）：Qwen2.5-7B、Llama-3.1-8B（本地 vLLM，温度 0）、Qwen3.8-flash（API，不思考，温度 0）读同一提示：指令、整条失败轨迹（动作、页面开头、最终奖励；事后视角）、该步的页面与全部可执行动作、原动作；并被告知执行者是谁（WS-A 写 a 7B language model，WS-B 写 an 8B language model，都是温度 0.7）。各提 2 个替代动作，必须在该页可执行且不同于原动作。在搜索页上提的是 `search[查询]`，查询可以自己写。
  3. **特权动作**（已知目标商品与选项，相当于 ALFWorld 的规划器）：
     - 搜索页：用目标商品的标题（小写）搜索；
     - 搜索结果页：目标商品在本页就点它，否则点 back to search；
     - 目标商品页：点第一个还没选的目标选项，选齐了就点 buy now；
     - 别的商品页和子页面：点 < prev。
  4. **随机**：点击页上，从不属于模型提议或特权动作的可点击项中随机取 1 个，并标记为“随机”；搜索页上，从指令里随机取 2–3 个词作查询。种子由（轨迹，位置）确定。
  5. 不另加别的。在点击页上，2–4 类基本都包含在 1 里，只是多了来源标记。
- **续跑**：7B、Llama 每个随机分支各 10 次（温度 0.7）加贪心 1 次；14B 晚到，只在 WS-A 上跑 20 次加贪心。续跑从修改后的状态接着跑到第 25 步，或者买下为止。种子由（执行者，条件，分支，序号）确定。
- **价值**：一个分支的价值是续跑的成功率（奖励 = 1.0 的比例）。主目标是净收益（替代分支价值 − 原动作分支价值），次要目标是修复后成功率；连续奖励作描述，两种都报。
- **统计**：同 6.9。分析单元是轨迹；轨迹 bootstrap 2,000 次，取 90% 百分位区间。部署者自己的选择用 5 选 5 评交叉拟合，分支内样本随机重排 50 次取平均；其他选择方式在评价执行者的全部 10 次上评价。所有选择规则的并列都按均匀随机打破（取平均）。单侧 p = (统计量 ≤ 0 的次数 + 1) / 2,001。每条轨迹、每个执行者各用一条随机数流。

**读数**
- **主检验**（Holm，单侧 α = 0.05，m = 5；还没有结果的按 p = 1 计入）：
  - WS-A：
    - **P1w**：匹配（7B 5 次选）− 7B 贪心 > 0；

  - 提出者 × 执行者，以及交互项。

**6.13 修订 3（2026-10-26 22:35 登记；任何正式运行之前，用户确认）：WebShop 的主目标改为奖励**
- 原因：S 中续跑的合并成功率只有约 7%（ALFWorld 6.9 为 20%）。每个分支 10 次续跑里大多是 0 次成功，以成功率为目标时，检验主要会因信号太稀而分辨不出。WebShop 的奖励（标准“分数”，买到部分符合的商品也有部分分）用的是同一批续跑，信息多得多（S 中平均 0.37）。
- 改为：**分支的价值 = 续跑的平均奖励**；买下即结束的分支取那一次的奖励。主检验（P1w、H1w、P2w、H2w、H3w；Holm m = 5）、阳性对照（下界 > 0.10）与 S1w 都按奖励算。**同样的读数按成功率（奖励 = 1）另算一遍，作为登记的次要读数**，不做 Holm，两种都报。设计、候选、续跑次数、选择规则都不变，也不多花续跑。
- 预测不变，指主目标（奖励）：P1w 0.05–0.15，H1w ≥ 0.05，H2w ≥ 0.05，H3w 0.03–0.15，阳性对照通过。另加一条：按成功率算的同名读数比按奖励算的弱（更接近 0、区间更宽）。

## 六之二、研究范围：只讨论单步修复（2026-10-22 定）

本文的修复单位是**替换单个动作**。理由：

1. 主问题是“代理评估会不会在候选修复中选错”，单步修复足以回答，且候选集合可完全枚举、oracle 可精确计算，这是测量干净的前提；
2. 多步修复的候选空间呈指数增长，属于另一个问题，已有 MRFR（最小修复族）、CAR（Shapley 分解）等工作；
3. Who&When、AgenTracer 等主流归因工作本身以“单个关键步骤”为单位，在同一框架内比较最直接。

**单步框架的边界本身是需要报告的发现**：对较弱的执行策略，大多数失败不存在“改掉这一步就能成功”的步骤。证据：v1 中 12/20 条轨迹在所有检查过的位置上都没有净收益 > 0.10 的单步修复；确认实验筛选中 73/107（68%）条 trap_step / timeout_return 轨迹在不可逆点上没有任何替代动作达到 3/10 成功，timeout_before_door 等类型在 v1 中全部为地板。这对以“存在决定性错误步骤”为前提的基准（Who&When、AgenTracer）提出了适用范围问题。论文中作为局限与讨论；多步修复作为明确的后续工作。

## 八、统计方案

- 分析单元是**轨迹**：轨迹聚类 bootstrap，同时对每个分支的成功次数做参数重抽样，选择与评价在每次重抽样中都重新计算；
- 选择与评价分离：独立批次或两折交叉拟合；
- 阳性对照决定结论能否成立；
- 每次正式实验前写下假设、统计量、δ、判断规则与轨迹选择规则（写入代码配置与本文件），结果出来后不再修改；
- 多重比较：确认实验的主检验 C1–C3 做 Holm 校正（单侧家族 α = 0.05）；次要检验、描述性比较与事后分析不校正，一律标注，并在论文中报告全部比较，不挑选。

## 九、威胁与局限

1. **地板效应**：60% 的轨迹不存在有效的单步修复。按失败类型筛选会改变样本总体，论文须说明结论只适用于“存在有效单步修复”的失败。
2. **样本量**：v1 只有 8 条有信号的轨迹；主结论必须来自确认实验。
3. **环境特殊性**：gridworld 的不可逆事件明确、预算固定，“不可逆点 ≠ 最佳修复点”可能部分来自预算结构，需要 ALFWorld 检验。
4. **单步修复**：只考虑替换一个动作；联合修复不在本文范围内，须明确声明。
5. **并列处理**：评估条件给出并列时按均匀随机打破（取平均）。对 oracle 这是它真实的信息量，但需报告 slack 打破等替代规则的结果。
6. **单一部署模型**：只有 7B。“换模型”的结论不能从温度实验外推。
